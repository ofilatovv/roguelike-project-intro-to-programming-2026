# Roguelike (консольна гра на C)

Покрокова консольна гра в жанрі roguelike. Гравець проходить поверхи підземелля, б'є ворогів, збирає монети та зілля й намагається набрати якомога більше очок, доки не загине. Написана на C, лише зі стандартною бібліотекою та функціями Windows для консолі (без зовнішніх бібліотек).

Головні фішки:
- кожен поверх генерується випадково (5–7 кімнат);
- покроковий бій з ворогами;
- мінімапа поверху;
- рекорд і кількість забігів зберігаються у файлі між запусками.

## Збірка та запуск

Потрібно:
- `gcc` (MinGW) і `make` (може називатися `mingw32-make`);
- Windows 10+ і Windows Terminal або PowerShell, розмір вікна не менше 100×24.

Працює тільки на Windows.

| Команда | Що робить |
|---|---|
| `make` | збирає гру (файл `roguelike.exe`) |
| `make run` | збирає і запускає гру |
| `make test` | збирає і запускає всі тести |
| `make clean` | видаляє `build/` і `roguelike.exe` |

```bash
make run
```

Рекорд зберігається у `stats.txt` в поточній папці, тому гру слід завжди запускати з одного й того самого місця.

## Керування та правила

### Клавіші

| Клавіша | Дія |
|---|---|
| `W` `A` `S` `D` | рух вгору / вліво / вниз / вправо |
| рух у бік ворога | атака |
| `Space` | почати гру на заставці / почати новий забіг після смерті |
| `Q` | вийти |
| `Ctrl+C` | теж вихід (термінал відновлюється) |

Стрілки та інші клавіші ігноруються.

### Позначки на екрані

| Символ | Що це |
|---|---|
| `@` | гравець |
| `E` | ворог |
| `#` | стіна |
| `.` | підлога |
| `$` | монета |
| `+` | зілля |
| `\|` і `—` | двері (сірі — зачинені, білі — відкриті) |
| `>` `<` `^` | вихід на наступний поверх |
| `◻` / `■` | мінімапа: кімната не зачищена / зачищена (кімната, де зараз гравець, підсвічена блакитним) |

Зліва від кімнати — мінімапа, справа — `SCORE`, `HP` та `FLOOR`, внизу — повідомлення про останню подію.

### Як грати

- Гравець починає з 5 HP на першому поверсі в порожній кімнаті.
- У кожній іншій кімнаті є вороги: на перших поверхах 1–3, далі їх стає більше (максимум 5). Поки хоч один ворог живий, двері та вихід зачинені.
- Коли всіх вбито, кімната зачищена, двері відкриваються. Іноді з'являється нагорода (див. нижче).
- Вихід на наступний поверх є в одній кімнаті, у найдальшій від старту (за кількістю дверей). Перемоги немає — гра триває, поки не закінчаться HP.

**Бій.** Кожен удар гравця забирає у ворога 1 HP (у ворога їх 3). Якщо ворог вижив, з шансом 70% він б'є у відповідь (−1 HP гравцю). Сам ворог не атакує, поки гравець його не вдарив. Виняток: якщо гравець даремно витратив хід (вперся в стіну чи зачинені двері), а ворог стоїть поруч, він гарантовано б'є. Вороги, які не стоять поруч, на кожному ході підходять на 1 клітинку.

**Очки:**

| Подія | Очки |
|---|---|
| вбитий ворог | +100 |
| монета | +100 |
| новий поверх | +500 |
| зілля при повному HP | +300 |
| кожне втрачене HP | −20 (очки не опускаються нижче 0) |

**Зілля** лікує 1 HP. З убитого ворога воно випадає з шансом 50%. **Нагорода за зачистку кімнати:** 25% монета, 25% зілля (50%, якщо у гравця менше 3 HP), інакше нічого.

## Структура проєкту

```
roguelike/
├── Makefile        збірка, запуск, тести
├── demo/main.c     точка входу і головний цикл
├── include/        заголовки (.h) усіх модулів
├── src/
│   ├── game.c      правила ходу, очки, смерть
│   ├── floor.c     генерація поверху
│   ├── room.c      кімната: двері, вороги, предмети, сітка 21×21
│   ├── minimap.c   дані для мінімапи
│   ├── combat.c    формула бою
│   ├── enemy.c     рух ворога
│   ├── stats.c     читання/запис рекорду
│   ├── render.c    малювання екранів
│   └── terminal.c  робота з терміналом і клавішами
└── tests/          тести основної логіки (бій, генерація, хід, мінімапа, нагороди, статистика)
```

Спільні константи та структури (`Entity`, `Room`, `Floor`, `Stats`) лежать у `include/types.h`. Увесь стан гри зібраний у структурі `Game` (`game.h`).

## Як це влаштовано всередині

**Ігровий цикл.** `main()` показує заставку, ініціалізує `Game` і запускає забіг. Далі цикл такий: намалювати кадр → прочитати клавішу → виконати хід. Один виклик `game_move_player()` — це дія гравця (крок, удар, перехід через двері) і потім хід усіх ворогів. Коли `game.dead` стає 1, показується екран смерті.

**Генерація поверху (`floor.c`).** Є стартова кімната. Далі кілька разів береться випадкова кімната й випадковий напрямок, і якщо там вільне місце на сітці та в кімнаті менше 3 дверей, то додається нова кімната з дверима в обидва боки. Вийшло дерево зв'язаних кімнат. Потім BFS від старту рахує відстані, і вихід ставиться в найдальшу кімнату на вільну стіну (знизу виходу не буває). Ворогів розставляє `room_spawn_enemies()` в усіх кімнатах, крім стартової.

**Кімната (`room.c`).** Кімната завжди 21×21, двері рівно посередині стіни. Плитки не зберігаються: щоразу, коли треба малювати, `room_build_grid()` складає сітку шарами (стіни → двері → предмети → вороги → гравець).

**Мінімапа (`minimap.c`).** Кожна кімната має координати на сітці. Мінімапа ставить кімнати через клітинку, а в проміжках малює лінії там, де є двері.

**Бій і вороги.** `combat_player_attack()` отримує `roll` (0–99) ззовні, тому її легко тестувати. Ворог (`enemy.c`) просто робить крок у бік гравця: спочатку по осі, де відстань більша, а якщо клітинка зайнята, то по іншій осі. Розумного пошуку шляху немає.

**Статистика (`stats.c`).** Це не характеристики персонажа, а файл `stats.txt` з двома числами: `runs_played` і `max_score`. Він оновлюється на початку кожного забігу і одразу, як тільки очки перевищили рекорд. Якщо файлу немає або він зіпсований, беруться нулі.

**Вивід (`render.c`).** Кадр збирається в один буфер і виводиться одним `fwrite`, тому екран не мерехтить. Замість повного очищення курсор повертається в кут (`\033[H`). Кожна клітинка — символ + пробіл, щоб поле не «їздило».

**Термінал (`terminal.c`).** Клавіша читається через `_getch()` без Enter. Читання **блокуюче**: гра покрокова, тому чекає на клавішу. Для кольорів вмикається режим ANSI-послідовностей, а для символів `—`, `◻`, `■` кодування UTF-8. Консоль відновлюється при виході (`atexit`).

## Тестування

```bash
make test
```

Кожен файл у `tests/` — окрема програма на `assert`. Якщо все добре, в кінці з'явиться `ALL TESTS PASSED`.

| Тест | Що перевіряє |
|---|---|
| `test_combat` | формулу бою: 70% відповіді на межі `69`/`70`, мертвий ворог не б'є |
| `test_floor` | на 200 різних seed: 1–3 двері в кімнаті, двері взаємні, один вихід, стартова кімната без ворогів |
| `test_game` | хід гравця: стіна, бій, смерть, монети, зілля, двері, новий поверх, очки та штраф |
| `test_minimap` | кількість кімнат і проходів, зачищені кімнати, підсвітка поточної |
| `test_reward` | шанси нагород (25% / 50% зілля при HP < 3) на тисячах розіграшів |
| `test_stats` | запис і читання файлу, відсутній і зіпсований файл |

Малювання (`render.c`) і ввід (`terminal.c`) тестами не покриті, їх перевірено вручну під час гри.
